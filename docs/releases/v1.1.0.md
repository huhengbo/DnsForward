# DnsForward v1.1.0

这是 DnsForward 在 v1.0.0 之后的一次集中整理与增强版本，重点放在可维护性、DNS 行为正确性、安全默认值和发布流程。

## 本版重点

- 建立标准 GitHub Actions CI：fmt、tidy、vet、test、race、staticcheck、govulncheck，以及 Linux/macOS/Windows amd64/arm64 构建。
- 建立自动 Release 流程，发布六个平台/架构产物并生成 SHA256 checksums。
- 项目结构整理为 `cmd/dnsforward/`，module path 规范为 `github.com/huhengbo/DnsForward`。
- 修复 `DOMAIN-SUFFIX` 边界误匹配、DNS 重写 QTYPE/地址族不一致、DoT TLS 校验等问题。
- 修正 DNS 缓存 TTL 递减与 NXDOMAIN/NODATA 负缓存语义。
- 增加客户端 CIDR allowlist 与全局并发上限，默认仅允许本机访问。
- 配置改为严格 YAML 解析，并将示例配置独立为 `configs/config.example.yaml`。
- RULE-SET 重载失败时保持旧 runtime，不再用残缺规则替换当前配置。
- 修正 UDP/TCP listener 错误处理与 SIGINT/SIGTERM 停止流程。
- 多上游只接受 `NOERROR` / `NXDOMAIN`，避免错误 RCODE 抢先返回。
- 使用 singleflight 合并相同 DNS key 的并发 cache miss，减少重复回源。
- 项目采用 MIT License。

## 升级注意事项

从 v1.0.0 升级时，请重点检查配置：

1. 运行时 `config.yaml` 不再随仓库维护。请以 `configs/config.example.yaml` 为模板保留自己的本地配置。
2. 配置现在使用严格 YAML 解析，拼写错误或未知字段会在启动时直接报错。
3. 默认 DNS 监听和客户端访问范围收紧为本机。局域网提供服务时，需要同时配置 `server.address` 和 `server.allow_cidrs`。
4. 使用 IP 形式的 DoT 上游时，必须使用 `tls://IP@hostname` 指定 TLS 证书校验名称，不再允许跳过证书校验。
5. Rewrite `target` 必须是有效 IP；A 查询只使用 IPv4，AAAA 查询只使用 IPv6。
6. 建议升级后先使用非 53 端口进行验证，再替换现有服务。

示例：

```yaml
server:
  address: "0.0.0.0:53"
  allow_cidrs:
    - "192.168.1.0/24"
```

## 下载与校验

Release 提供：

- Linux amd64 / arm64
- macOS amd64 / arm64
- Windows amd64 / arm64
- `checksums.txt`

每个压缩包都包含 `config.example.yaml`。升级前建议使用 `checksums.txt` 校验下载文件的 SHA256。
