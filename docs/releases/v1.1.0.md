# DnsForward v1.1.0

> 本版本是 v1.0.0 之后的一次集中整理与增强，重点放在 DNS 行为正确性、安全默认值、可维护性和自动发布流程。

### ✨ 主要更新

- **标准化项目结构**
  - Go 入口与实现整理到 `cmd/dnsforward/`。
  - module path 规范为 `github.com/huhengbo/DnsForward`。
  - README、示例配置、贡献说明与安全说明完成标准化。

- **自动化 CI / Release**
  - CI 覆盖 fmt、tidy、vet、test、race、staticcheck、govulncheck。
  - 持续验证 Linux / macOS / Windows 的 amd64 / arm64 构建。
  - Release 自动生成六个平台/架构压缩包和 `checksums.txt`。

- **DNS 正确性修复**
  - 修复 `DOMAIN-SUFFIX` 域名边界误匹配。
  - DNS Rewrite 严格遵循请求 QTYPE 与 IP 地址族。
  - 修正缓存命中时 TTL 递减及 NXDOMAIN / NODATA 负缓存语义。
  - 多上游仅接受 `NOERROR` / `NXDOMAIN`，避免 `REFUSED`、`FORMERR`、`SERVFAIL` 抢先返回。

### ⚙️ 优化调整

- 配置拆分为本地运行配置与 `configs/config.example.yaml` 示例配置。
- 配置启用严格 YAML 解析，未知字段直接报错。
- RULE-SET 任一加载失败时，本次 reload 整体失败并保留旧 runtime。
- UDP/TCP listener 失败会正确结束进程；支持 SIGINT / SIGTERM 正常停止。
- 相同 DNS key 的并发 cache miss 使用 singleflight 合并，减少重复回源。

### 🔒 安全与稳定性

- 默认 DNS 监听与访问范围收紧为本机。
- 增加 `server.allow_cidrs` 客户端 CIDR allowlist。
- 增加 `server.max_concurrent_queries` 全局并发查询限制。
- DoT 不再允许缺失 SNI / 校验名称时跳过 TLS 证书校验。
- 使用 IP 形式的 DoT 上游时必须使用 `tls://IP@hostname`。
- 项目正式采用 MIT License。

### 📦 升级说明

- **建议先核对配置再覆盖升级**：v1.0.0 用户升级到 v1.1.0 前，请先对照新的 `configs/config.example.yaml`。
- **运行时配置不再随仓库维护**：保留自己的 `config.yaml`，不要直接用仓库更新覆盖本地配置。
- **严格 YAML**：拼写错误或未知字段会在启动时直接报错，需要先修正配置。
- **局域网监听**：如果需要为局域网提供 DNS 服务，请同时设置 `server.address` 和 `server.allow_cidrs`。
- **DoT 配置变化**：IP 形式上游必须显式指定 TLS 校验名称，例如 `tls://1.1.1.1@cloudflare-dns.com`。
- **Rewrite 配置变化**：`target` 必须是有效 IP；A 查询只使用 IPv4，AAAA 查询只使用 IPv6。
- **建议验证步骤**：升级后可先监听非 53 端口进行验证，确认解析、规则和上游均正常后再替换现有服务。

局域网示例：

```yaml
server:
  address: "0.0.0.0:53"
  allow_cidrs:
    - "192.168.1.0/24"
```
