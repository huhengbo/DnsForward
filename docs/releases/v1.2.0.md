# DnsForward v1.2.0

> 本版本重点补齐 Linux 一键安装、内置 Web 管理、管理界面优化和单用户登录认证；从 v1.1.0 升级前建议先阅读下方升级说明。

### ✨ 主要更新

- **Linux 一键安装与服务管理**
  - 新增 `scripts/install.sh`，支持 Linux amd64 / arm64。
  - 自动从 GitHub Release 下载对应架构产物并使用 `checksums.txt` 校验 SHA256。
  - 安装后提供 `dnsforwardctl`，支持 `start`、`stop`、`restart`、`status`、`logs`、`uninstall`。
  - 使用 systemd 管理服务，运行配置位于 `/etc/dnsforward/config.yaml`。

- **内置 Web 管理**
  - Web 管理直接内置在现有 `dnsforward` 二进制中，无需单独部署前后端。
  - 支持运行状态、版本、DNS/Web 地址和配置文件路径查看。
  - 支持直接查看、编辑和校验完整 YAML 配置，包括 upstream、Rewrite 与 RULE-SET。
  - 配置保存使用原子写入，校验通过后立即热重载。
  - Web 端可查看 Health、Metrics 和最近 200 条进程日志。

- **Web UI 优化**
  - 改为仪表盘式响应式布局。
  - 优化桌面与移动端显示。
  - 增加版本、DNS、Web、认证状态卡片。
  - 配置、日志和观测区域重新整理，校验/保存/刷新结果反馈更明确。

- **单用户登录认证**
  - 新增 `server.web_password_hash`。
  - 配置中只保存带盐迭代密码哈希，不保存明文密码。
  - 新增 `dnsforward -hash-password`，从 stdin 读取密码并输出可写入配置的 hash。
  - 登录使用随机内存 Session，默认 12 小时过期；服务重启后会话自动失效。
  - Session Cookie 使用 `HttpOnly` 和 `SameSite=Strict`。
  - 支持退出登录；修改密码哈希后会自动清除旧会话。

### ⚙️ 优化调整

- Web 管理保持原生 HTML/CSS/JavaScript 内嵌实现，没有引入 Vue、React 或独立前端工程。
- 没有引入数据库、JWT、OAuth、RBAC 或额外用户系统。
- 密码派生使用 Go 标准库实现 PBKDF2-HMAC-SHA256 风格的带盐迭代派生，未新增第三方依赖。
- Web 配置保存继续复用现有配置校验与 runtime 原子替换逻辑，不增加新的配置管理框架。

### 🔒 安全与稳定性

- Web 管理当前仍强制只监听 loopback：`127.0.0.1`、`::1` 或 `localhost`。
- 即使开启密码认证，也不会直接允许 `0.0.0.0` 或局域网地址，避免在没有 HTTPS 的情况下暴露登录页面。
- 未登录时，管理 API、Web 端 `/metrics` 和 `/healthz` 都返回 `401 Unauthorized`。
- 修改 `web_password_hash` 后已有 Session 会立即失效。
- CI 已通过普通测试、race、staticcheck、govulncheck，以及 Linux/macOS/Windows amd64/arm64 六平台构建。

### 📦 升级说明

- **可直接升级**：v1.1.0 用户可以直接替换二进制升级到 v1.2.0。
- **旧配置兼容**：如果旧配置没有 `web_address` 或 `web_password_hash`，不会因为升级自动开启远程 Web 或强制登录。
- **启用 Web**：在配置中设置 `server.web_address: "127.0.0.1:8080"`，然后重启进程。
- **启用密码登录**：先运行：

```bash
dnsforward -hash-password
```

然后将输出写入：

```yaml
server:
  web_address: "127.0.0.1:8080"
  web_password_hash: "pbkdf2-sha256$200000$...$..."
```

- **监听地址变更**：修改 `web_address` 本身后需要重启进程；其他可热加载配置仍可从 Web 保存后立即生效。
- **Linux 安装用户**：一键安装后配置位于 `/etc/dnsforward/config.yaml`，管理命令为 `dnsforwardctl`。
